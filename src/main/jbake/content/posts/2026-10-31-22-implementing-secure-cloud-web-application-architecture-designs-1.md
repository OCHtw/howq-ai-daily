**核心理念：即使 Web 主機遭入侵，也無法直接存取核心資料庫。**

由於資安事件越來越多，小編決定重新設計系統架構。從常見的雲端網頁服務架構即時存取後端API(通常會直接讀取資料)，調整成比較麻煩的前端網頁以預先產生為主。即使需要讀取最新資料，然後被轉成非同步方式，取得所需內容。阻隔前端直接讀取後端資料庫被讀取的頻率與機會。

### 架構特色

1. **零公開入口**：EC2 全部私有化，透過 Cloudflare Tunnel 進入，結合 CDN、WAF、LB 防護。
2. **三區安全隔離**：SG-A（Web）、SG-B（快取／訊息）、SG-C（資料），各自獨立權限，降低橫向入侵風險。
3. **最小權限設計**：Web 層僅能讀取授權快取、發布指定訊息，不能直接連接資料庫。
4. **四層讀取加速**：CDN（L0）→ Caffeine（L1）→ Redis（L2）→ RDS（L3），減少資料庫負載與被全部撈取機率。
5. **事件驅動更新**：RabbitMQ 負責非同步處理，Redis輔助快取更新與資料載入。
6. **輕量 Web 技術**：Spring Boot MVC + Thymeleaf + HTMX，採 Server-Side Rendering，避免大型 SPA 的複雜度。
7. **資料獨立保護**：資料服務集中管理 JPA、資料寫入與 Audit，搭配獨立帳號、權限及重要資料加密。

### 設計重點

**不是單純防止入侵，而是假設 Web 已遭入侵，仍透過網路隔離、最小權限與非同步架構，限制攻擊者能造成的損害。**

並同時兼顧低資源消耗、水平擴充能力，以及微小服務初期的營運成本。


### 架構缺點：使用者UX體驗容易不佳

  * 非即時式設計回應久：使用者操作體驗會很差，因為需要等待結果。3.0 秒是電商放棄極限。根據 Google 研究，網頁載入若超過 3 秒，將有 53% 的行動裝置用戶直接關閉網頁。但目前因短影音影響現代使用者專注力，故網頁回應以1.0 秒內為佳，使用者的思維不會被打斷，雖然感覺得出有停頓，但不需要額外的讀取提示。
  
  * 網頁同步更新不易：容易造成不同主機手上快取資料不同，當使用者又被切換到不同主機提供服務時，會造成困擾與交易失敗。


**改善方向：透過AI強化預測使用者所需網頁，並提前準備。**
